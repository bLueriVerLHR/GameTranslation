## 1. TyranoScript `[bgmovie]` 自动播放策略卡死

TyranoScript 引擎的 `[bgmovie]` 在 `tyrano/plugins/kag/kag.tag_ext.js`
里直接 `video.play()`，被拒后 `wait_bgmovie` 永久等待 → 标题黑屏冻结
（PC 浏览器和 JoiPlay 都可能复现，取决于该 origin 的播放权限历史）。
修复已固化进 `tyrano/pipeline.py fix-autoplay`（幂等、可逆）：`play()`
promise 被拒时挂一次性 click/touchstart/keydown 监听，首次用户交互后
重播并移除监听。验证方式：把真实交付构建里手工打的补丁反解成原始文件，
用模块重打，`cmp` 与交付构建字节一致。注意 minified 文件里
`video2.play()j_video2.css` 无分号（ASI），替换时保留该特征。

## 2. KAG3 → TyranoScript 移植：停车标签与可点击地图（KiriKiri 引擎移植）

- **KAG3 `[s]` 不是点击等待**：本作（改版 KAG3 系统）的 `s` 处理器是
  `inSleep=true; return -1` = 场景结束，点击不做任何事；流程恢复只靠
  `window.process()/goToLabel`、链接、地图。移植到 Tyrano 时若映射成 `[l]`
  （点击推进），标题/菜单死区点击会误推进、串标签。正确做法：自定义
  `[kag3stop]` = stronglyStop + hideEventLayer（事件层隐藏，点击无效），
  地图/链接/jump 不依赖流程状态照常工作。转换期需确认目标游戏所有 `[s]`
  后跟的是标签/endmacro（抽样全量统计，而不是凭经验）。
- **KAG3 可点击地图的生命周期**：地图挂在图层上，`window.process()`/jump
  **不清地图**；只有「该图层加载新图片」（`loadImages` →
  `clearProvinceActions`）或显式 `[mapdisable]` 才清。挂接方式有两种：
  显式 `[mapaction]`，以及 loadImages 的**自动挂接**（`X.ma` 与图片同名时
  自动加载）。移植时若在跳转时清地图，标题 hover（onenter → process 跳转）
  会把地图清掉 → 之后点击全部失效。按原语义只在该图层换图/显式 disable 时清。
- **`[s]` 等标签映射的正则要保行尾**：`re.sub(r'^\[s\]\s*$', ...)` 的 `\s*$`
  会吞掉 `\r\n`，下一行标签被并到上一行（`[s]` + `*label` → `[kag3stop]*label`，
  标签行变成文本）。改成 `r'^\[s\](\s*)$'` + lambda 保留 group(1)。
- **KAG3 `[ch]` 是正文渲染标签**：名字窗、选择肢文字、菜单项全靠它
  （`[ch text=%n]`、`[ch text=&sentaku[0].txt]`）。移植时转发给目标引擎的
  文本标签（Tyrano 的 text 标签自己 nextOrder，shim 不要再推进）。no-op
  shim 会让名字/选择肢/菜单文字全部空白——这类"看似无害"的 no-op 名单要
  逐个核对用途。
- **右击推进的屏幕**：`[rclick jump=true storage=X target=Y]` 驱动的屏
  （coming soon/lineup 等）在移动端没有右击会卡死。移植时实现 rclick 标签
  + 触摸兜底（无活动地图时左键也触发）。
- **多标签行不能只按标签重建**：正文可能夹在 `[font]`、`[r]`、`[l]` 等
  标签之间。扫描器必须保留每个标签的源区间，只改写区间本身，再把间隙正文
  原样拼回。引号内的 `]` 与转义括号也要纳入测试。
- **`@tag` 与 `[tag]` 必须经过同一转换路径**：先把行首语法规范化，再执行
  资源路径、等待和标签语义改写；提前返回会造成两种写法行为分裂。
- **相邻标签分隔符要在解析前规范化**：部分 KAG3 脚本用 `]\[` 连接标签。
  Tyrano 会把反斜杠当转义并把后一个标签显示成正文，严重时还会留下未闭合的
  条件块。只删除紧跟 `]` 且紧邻 `[` 的反斜杠，不能吞普通正文转义。
- **选择文字应写入当前链接 span**：Tyrano 的链接标签会创建活动 span；
  `[ch]` 若另建平级 span 或段落，显示文本与点击目标会分离，并可能在重复进入
  时留下重叠区域。使用当前消息层、当前段落和当前 span，选择结束后按引擎
  生命周期清理。
- **音频异步回调必须校验播放实例**：复用声道时，旧元素的 `ended`、`error`
  或 `play()` 拒绝可能晚于新声音到达。回调只有在元素仍是声道当前实例时才能
  修改状态；播放前先设状态，并覆盖同步抛错与 Promise 拒绝两条失败路径。
- **增量转换仍要重建资产索引**：`--scenario-only` 会保留输出目录中的图片、
  音频与地图文件。若只从精简源目录生成运行时映射，省略扩展名的引用会退回
  Tyrano 默认文件夹并产生 404。增量模式须把现有 `data/` 资产合并进映射。
- **资产索引合并必须是「图片优先」，不能用 setdefault**：KAG3 的可点击地图
  描述文件与同一屏的画面常共用基础名（`X.MA` 与 `X.png`）。精简源目录里
  往往只剩 `.MA`（图片常经由 `[image storage=%param]` 这类宏参数引用，离线
  收集引用时容易漏掉），先写入的 `.MA` 会占住基础名，后合并进来的图片被
  `setdefault` 丢弃。运行时表现是**画面全黑但点击区域照旧生效**：省略扩展名
  的图片引用把 `.ma` 文本文件塞给 `<img>`，浏览器解码失败且不报错（HTTP 200、
  `js_errors: 0`），而区域图 `X_P.png` 是独立映射，命中测试仍然正确。实测
  后果：菜单不可见却可点，误触不可见的退出项会走到 `[close]`，确认后
  `window.close()` 直接关掉窗口（app 模式/无头窗口真会关，普通标签页会被浏览器
  拦下）。合并规则必须显式表达「图片胜过同名非图片」，两张图片之间仍由源目录
  决定。排查手法：对照运行时映射中 `X` 与 `X.png` 两个键的值（值为 `.ma` 即命中），
  并核对服务器访问日志里该图片是否**从未**被请求。
- **全屏点击捕获必须先排除控制界面**：可点击地图常在 document 捕获阶段处理
  事件；若命中后停止传播，后加的手机工具栏即使层级最高也收不到点击。命中
  测试应把工具栏、按钮和表单控件识别为界面元素，让事件继续到目标控件；工具栏
  自己处理后再停止传播，避免同时推进剧情或触发地图。
- **移除桌面按钮后也要处理空外框**：只丢弃 `[button]` 会留下原作给按钮行准备的
  小消息层，结果是正文旁边仍有一排空底图。可在 `[position]` 执行后按画布比例
  分类：宽而高的是正文框，中等宽度的矮框是名字框，极窄矮框才是桌面辅助框。
  名字框必须设置最小宽度门槛，否则小按钮占位会被误判成名字框重新显示。
- **选择面板要从链接元素反向标记整层**：`[ch]` 同时用于名字和选择文字，不能把
  所有 `[ch]` 都居中。仅当当前 span 属于 Tyrano 的链接事件元素时，才给选项、
  消息内层和所在图层加分类；随后把提示和全部链接排入一个自适应高度面板。源宏
  可能只给第一项设置白色，移动样式需要覆盖选项内部 span 的颜色，否则后续项会
  在深色衬底上显示成黑字。
- **替换了控制面板就应隐藏 Tyrano 默认菜单图标**：默认右下角圆形按钮会覆盖正文
  或选择区。自定义面板已连接真实存读档、历史、自动和快进动作时，可隐藏默认
  `button_menu.png`，并保留一个至少 44 像素的折叠入口。
- **隐藏消息必须走引擎完整生命周期**：只调用 `hideMessageLayers()` 会隐藏画面，
  却不会执行 `hidemessage` 标签恢复事件层所需的状态转换。快进中断后尤其容易
  留下“画面恢复但点击和回车均不能推进”的状态。隐藏前应退出快进，隐藏时调用
  原生 `hidemessage`；恢复时显示消息层、清掉点击中文字状态，并在非强停点重新
  显示事件层。
- **系统菜单必须串行打开并独占界面层**：Tyrano 的存档、读档和历史入口会异步
  填充同一个菜单层。连续点击时若不判断菜单层状态、不先清空旧内容，页面会互相
  叠加。打开前应设置 pending 状态、清空菜单层并隐藏游戏工具栏；菜单关闭后再按
  菜单层可见性恢复工具栏。
- **选择宏会留下空换行 span**：选项之间的 `[r]` 常生成仅含 `<br>` 的 span。
  若把所有非链接 span 都当作提示文字，它们会各自取得块级外边距，造成选项纵向
  间隔异常。应按可见文字区分提示与空隙，隐藏空隙；选择完成后同时删除选项、提示
  和空隙节点，并移除消息层的选择态 class，防止后续对白进入旧面板。
- **选择跳转发生在 document 冒泡清理之前**：链接自身的点击处理会同步开始目标标签，
  新正文可能在冒泡阶段清理旧选择层之前写入。应在捕获阶段只标记“正在离开选择”，
  再由下一次正文标签清除旧节点并创建新段落；延迟删除时只删除点击前保存的节点，
  避免误删目标分支立即生成的新选择。
- **菜单快进要调用原生 `skipstart`**：直接 `setSkip(true)` 只改变标志，不会把停在
  `[l]`/`[p]` 的标签泵向前推进，所以按钮看似开启却没有效果。非打字状态下调用
  `skipstart`，打字过程中才直接开启标志；关闭时仍走 `setSkip(false)`。
- **大型鉴赏脚本会突破 Tyrano 的两个固定假设**：KAG3 可用 `[laycount]` 临时请求上百
  个数字图层，而 Tyrano 默认只创建配置中的少量图层；同时 Tyrano 的条件块搜索最多
  查看 2000 个标签。鉴赏缩略图会因此报图层为空或找不到 `[endif]`。兼容层应按需调用
  引擎的图层创建接口，并把搜索上限改为当前场景剩余标签数。
- **旧动画描述不能当作浏览器图片加载**：有些 KAG3 动画插件用带前缀的描述名引用
  一张同名代表帧，描述数据不会被浏览器图像标签解码。若没有可重建的帧序列与时序，
  应明确降级到已转换的代表帧，避免黑屏；视频型鉴赏仍走媒体转换和视频播放路径。

## 4. 宏体里的 `[return]`：Tyrano 会跳错地方（鉴赏回放结束不回图库）

**症状**：从鉴赏进 CG 回放，场景结束后**不回到图库**，而是直接接上后续剧情
（场景标志未清除、调用栈看似正常，无报错）。

**机制**（已实测定位，引擎源码里也写了）：

- KAG3 的宏是**解析期内联**的，所以宏体里的 `[return]` 等价于「调用方顺序流里的一条
  普通 return 标签」→ 从最内层 `[call]` 返回（“回放结束”正是这个用法：
  `[macro name=PV_END]` → `[if exp="tf.now_pv == 1"][return][endif]`）。
- Tyrano 的宏是**运行期帧栈**（`stat.stack.macro`），引擎自己的 `[return]` 只做
  `popStack("call")` + `nextOrderWithIndex(caller)`，**不清理宏帧**；引擎注释直接写
  了限制：“マクロからの場合、ここから、呼び出さないとだめ。**だから macro で
  return は使えない**”。
- 实测轨迹（修复前）：`return` 之后流程回到 **宏的调用点**（场景末尾那条剧情行），
  接着往下演（`newgame.ks:9008…`），`seen_set.ks` 的收尾（清除场景标志 → 跳回图库）
  根本没执行。

**修法**（兼容层，通用，无游戏专属数据）：

- 包 `kag.pushStack`：推入 `call` 条目时把**当前宏栈深度**存进该条目；
- 包 `[return]` 标签：交给引擎前先把 `stat.stack.macro` **截断回该深度**（丢掉被调
  用方开的所有宏帧，保留调用方自己的帧），随后引擎的返回就会落到正确的调用点。
- 这就是 KAG3 内联宏的等价语义；实测修复后轨迹：
  `return(define.ks:2964) → jump seen.ks (seen_set.ks:257)`，宏栈/调用栈归零，
  落在图库首页（已验证该页正常渲染）。
- 回归测试：`tests/test_kag_shims.py::TestMacroReturnCompat`（垫片必须同时包装
  `pushStack` 与 `[return]`，且截断发生在委托给引擎之前）。

**调试手法**：这类“静默跳到别处”的问题靠**包装引擎派发点**定位：
`kag.ftag.master_tag[name].start`（而不是 `ftag.startTag`）才是顺序流的真正执行点；
再包 `kag.endStorage` 就能看到回栈与后续跳转。

## 3. `[iscript]` 里的函数声明不会成为全局函数（静默哑掉一整类功能）

**症状**：BGM、音效都正常，但**人物对话语音完全没有**（既没声音、也没有网络请求），
语音重播按钮、自动模式、声音测试页也一起失效。控制台**无任何报错**。

**机制**（已实测定位）：

- KAG3 的 `[iscript]` 代码在**全局作用域**执行，所以 `function CharVoiceFlgCheck(){}`
  是全局函数；Tyrano 用 `evalScript()` 里的 `eval(str)` 执行同一段代码，
  **函数声明只会落在调用方的函数作用域**，不会挂到全局。
- 于是游戏自己的实现不可见，调用点（`[if exp="CharVoiceFlgCheck(mp.vo)==1"]`）
  静默落到**运行时垫片的兜底桩**（`window.X = window.X || function(){return 0;}`）→
  判定永远为假 → 整块语音播放被跳过。与 `[eval]`/`[embScript]` 不同，
  这种失配既不报错也不警告。（`var x = ...` 同样需要导出，转换器早就在做。）
- **判据**：在页面里比对「函数是否存在」与「返回值」——
  `typeof window.Foo` 是 function 但 `Foo(真实参数)` 返回兜底值（且不带参数求值）就是
  桩函数在接管；同时看服务端请求日志：修复前 `GET /data/sound/v_*.ogg` **为 0 次**，
  修复后立刻出现 200。
- **修法**：转换器在生成 `.ks` 时把 iscript 顶层名字导出为全局
  （`kirikiri/kag/scenario.py::_export_globals`）。注意声明的两种花括号风格都要认，
  `function f(a) {` 与 `function f(a)` 换行 `{` **在本类语料里各占一半**；
  旧实现只认同行花括号，导致 16 个顶层函数里有 11 个没被导出。
- **回归测试**：`tests/test_convert_kag.py::TestExportGlobals`（同行/换行花括号、
  嵌套函数不导出、匿名函数表达式不导出）。
- **连带恢复**：本次修好的是语音、语音重播、自动模式、声音测试页与一个音量拆分
  辅助函数——凡是「由游戏 iscript 定义、又被 `[exp]/[if]/[hact]` 调用」的函数都属同一类。
