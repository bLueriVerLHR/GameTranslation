## 1. `.ks` 写回

### 1.1 写回链的输入必须是原版场景树

**现象**：拿已译构建当输入重跑写回，绝大多数行被原样拷回（命中 119 行，正确
输入下是 540 行），行数骤降而工具不报错。只改译文里的一类字符（把一串中点
改成更长的中文省略号）时也会重跑整条写回链，链上其它记在**构建**里的改动被
一并还原——某次重写后构建里出现 61 处 `.mp3` 悬空引用，而该构建此前是好的。

**判据**：命中数就是输入方向的判据。写回必须从**日文原版的场景树**出发；
`apply_tyrano_translation.py --scenario-dir <已译构建>` 能跑但结果无意义
（键无命中）。原版里永远不会有的东西（如已改写的资源引用扩展名）一旦从原版
重写就会被还原。

**处置**：重写后必须重跑引用审计（按扩展名数一遍 `storage=`、`clickse=`、
`enterse=`、`decidese=`、`cancelse=` 等引用）与验收，别只看译文；把已处理
构建当输入重跑任何步骤前，先问「这一步的输入是原版还是构建」。

### 1.2 省略号分级改写（`・` → 中文省略号）

译文里 `・` 是禁项，原文的 `・` 串按长度分级改写成中文省略号：

| 原文点数 | 省略号字数 |
|---|---|
| 2～3 | 2（`……`） |
| 4～5 | 4（`…………`） |
| 6～8 | 6（`………………`） |
| 9 以上 | 8（封顶） |

机械做法：逐行把日文键里的第 i 个 `・` 串对应到译文里的第 i 个 `…` 串，只改
长度，不动其它字符。

- **行内串数可能不等**：译者会合并（`イくっ・・・イぐぅ・・・` 只留一个
  `……`）或拆分停顿，也可能原文用的是另一个字符（`‥‥` 是 U+2025 双点前导符，
  不是 `・`）。这些行整行不动，或从左按序配对后列出人工过目，不能猜。
- **改完要重跑门禁**：假名与换行门禁、构建级扫描照旧适用（省略号不在假名类
  里），并目视确认变长的显示文本没有溢出消息窗口。

### 1.3 `.ks` 的键与写回契约

**判据**：键是**去掉首尾空白的整行**，标签原样保留，只翻日文片段。收集范围是
`[tb_start_text]` 与 `[_tb_end_text]` 块内的行（`#名字` 行与文本行），加上带
日文 `text="..."` 属性的 glink、`tb_ptext_show`、`p_notify`、
`tb_alert_dialog` 行；注释行、空行、括号不平衡的行与纯标签行从不提取。
`name="..."` 属性（`[ptext name="chara_name_area"]`）是元素标识符，不译。
说话人名是共享键（`#つむぎ` 出现几百次只占一个键），词表定名后一次替换全部
生效。

**处置**：写回是整行替换，保留原缩进、行尾与文件编码，译文里每个标签逐字节
不变。外部字典的键是**渲染后的文本**，而工作包的键是带标签的整行，所以烘焙
外部字典等于按整行重建标签与文本段。

## 2. 场景之外的引擎文案

### 2.1 `tyrano/lang.js` 是引擎自己的玩家文案

**现象**：剧情全中文，一按「回标题」弹出日文确认框。

**判据**：`tyrano/lang.js` 装的是引擎自己的玩家可见文案（回标题确认框、无存档
提示、脚本报错、补丁提示……），它在 `data/scenario` **之外**，任何 scenario
提取器都看不到。判定手法：把构建里所有含假名的文件按**非注释行**过一遍
（注释里的日文不算），逐个问「这行会不会被画出来」。`tyrano/html/*.html`（仅
注释）、`data/system/KeyConfig.js`（仅注释）、插件 `*.builder.js`（仅注释与
`console`）都属安全；`lang.js` 的 `word` 对象才是真文本。

**处置**：`gt-tyrano localize-ui`（模块 `tyrano/ui_lang.py`），仓库自带可复用
映射 `tyrano/ui_lang_zh.json`。

- **按键匹配，不按原文匹配**：原文随引擎版本微调，键名稳定。
- **机械门禁逐条拒**：占位符集合（`{ name }` 等）、`\n` 个数、残留假名、空值
  任一项不合格，该条目保持原字节并让命令非零退出。翻译质量靠执行者，但「会把
  引擎消息改坏」的错不允许上盘。
- 单引号风格要跟随原文：stock 文件只在句子含 `"` 的条目上用单引号，写回时选
  不需转义的引号字符。

### 2.2 `[iscript]` 里的可见字符串提取器不收

**现象**：游戏自己的 `[iscript]` 代码里嵌着真要给玩家看的字符串（典型：配置
画面的文字速度样张 `tf.text_sample = '…'`）。提取器有意不碰 `[iscript]`
（那是代码，里面绝大多数是逻辑），于是它既不在 `ja.txt` 里，也不会被任何门禁
抓到。

**判据**：交付前用 `rg` 找 `[iscript]` 与 `[endscript]` 之间带引号的日文，逐个
确认是否显示。同类还有 `tf.*` 赋值、`TG.config.* = "true"` 之类的配置行，它们
带的**行尾注释**日文永远不用译。区分判据就是「会不会被画出来」。

**处置**：要译的字符串单独翻一行，再整行替换，保留 `变量 = '…';` 的代码骨架。
