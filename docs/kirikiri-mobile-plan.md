# KiriKiri2 → TyranoScript 手机可玩构建改进计划

更新日期：2026-09-13。状态：第二轮阅读、选择、菜单、隐藏恢复和补丁覆盖修复
已完成桌面浏览器回归；Android 实机与完整系统功能仍待验收。

## 1. 目标与优先顺序

将已有 KAG3 转换框架推进到可在 Android JoiPlay 上实际游玩的构建，尽量
保留原作的阅读、选择、音画与操作体验。优先修好正在影响试玩的部分，
不以“转换命令成功”“首页能打开”作为交付标准。

| 优先级 | 用户反馈 | 期望结果 |
| --- | --- | --- |
| P0 | 对话缺少半透明黑底，文字不清楚 | 对话窗有稳定的黑色半透明衬底，背景仍可见 |
| P0 | 说话者位置不正确 | 名字位于底部对话框的左上方，不再跨全屏居中 |
| P0 | 选择画面有重复、错位和误导 | 一项对应一个正确目标，显示与点击范围一致 |
| P1 | 快进太慢，不便调试 | 有显式调试快进，能迅速抵达目标位置并停在选择处 |
| P1 | Tyrano 默认面板不足 | 建立与原作常用操作对应的手机控制入口 |
| P2 | 语音、动画、鉴赏等功能不全 | 按真实调用逐项补齐，并记录仍然降级的行为 |

语音和动画中若存在阻断推进、破坏分支或导致错误状态的问题，提前按 P0
处理。完整鉴赏界面放在基础游玩闭环之后，避免同时重写全部系统。

## 2. 当前依据与不确定项

目前已定位 `kirikiri/convert_kag.py`、本地 Tyrano 引擎骨架、工作副本和浏览器
测试构建。第一轮已用合成场景复现并验证对话衬底、名字位置、选择重复和点击
目标；真实脚本构建已通过启动脚本与资源解析检查。用户最近的 Android 构建
仍需重新生成后实机确认，不能用桌面浏览器结果代替。

代码审查发现的具体问题：

- 多标签行只用标签重建输出，会丢失标签之间的正文。例如
  `[font size=24]Hello[r]World[l]` 中的两段文字会被删除。
- `@tag` 提前返回，绕过与 `[tag]` 对应的资源解析和语义转换。
- 声音通道切换后，旧音频的结束、错误或播放拒绝回调曾能修改新音频状态。
  现已绑定到所属播放实例，并覆盖结束、错误、拒绝、循环、停止和同步异常测试；
  真实对白语音仍需浏览器与 Android 逐场景试听。
- 原作书签、历史和自动播放相关的部分 API 仍是空操作。界面存在不代表
  功能存在，也不能直接断言所有 Tyrano 自带替代入口不可用。

环境方面：项目虚拟环境在受限执行环境内不能直接启动；已用同平台的内置
Windows Python 运行不依赖图片二进制扩展的回归测试。最终合并前仍须用项目
虚拟环境跑完整测试；素材重编码不在本轮第一阶段内。

## 3. 阶段一：建立可复现基线

1. 确认当前试玩构建、解包工作副本、引擎版本和构建参数；保留原版与旧构建。
   新工作产物放系统临时目录，沿用可用素材缓存，避免重复全量处理。
2. 在本地工作目录建立问题记录：入口、操作步骤、预期、实际表现、脚本位置、
   构建版本。游戏名、截图、原始台词及专属参数不进入公开仓库。
3. 为六项反馈各找最短复现路径。定点回归用于确认修复；另随机抽样不同场景，
   检查是否破坏其他页面，二者不能互相替代。
4. 分开记录转换器、生成脚本、运行时兼容层和素材问题，不靠一次性产物补丁
   掩盖上游错误。每次修复必须能由转换命令重新生成。

完成条件：能够说明“哪份构建、哪一步、哪个表现有问题”，并保留修改前证据。

## 4. 阶段二：对话框、名字与选择（首个试玩里程碑）

### 对话与名字

- 核查 `[position]`、`[current]`、`[style]` 和消息页切换；区分全屏消息层、
  窗口外框和文字区域。黑底只覆盖对话窗口，不覆盖整个场景。
- 优先使用原作窗口几何信息。缺失时通过外部配置提供衬底颜色、透明度与边距，
  不把某款作品的坐标写死为所有游戏的默认值。
- 名字区域锚定对话框左上方；姓名换行、正文换页、隐藏窗口和前后页切换时
  都应保持一致。确认名字框与正文框的层级和文本对齐规则。
- 修复混合标签正文丢失、`@` 与方括号语法转换不一致的问题，添加合成回归测试。

验收：明亮与暗色背景上都能看清正文；长台词不越界；名字不会漂移或压住
正文；隐藏窗口后衬底一起消失；不破坏图片式消息窗和无名旁白。

### 选择

- 追踪选择生成、图层替换、前后页复制、事件注册和清理的整个生命周期。
  先区分“脚本生成重复”“旧元素残留”“点击处理重复”三类原因。
- 校对每一项的标签、顺序、目标和条件；点击区域不能错配到另一项。
- 检查普通点击、触摸、重复进入、读档返回和快进抵达选择的行为。

验收：屏幕上的每一项只出现一次；点击一次只推进一次；进入正确分支；
选择后旧按钮消失；所有可见选项都能操作，空白处不会误选。

完成条件：产出一份可供用户试玩的候选构建，集中确认阅读和选择体验。

## 5. 阶段三：调试快进与语音可靠性

- 审查既有 `--fast-skip`，分别测量文字、定时等待、转场和媒体造成的耗时，
  不把所有等待一律删掉。记录同一路径到达目标位置的时间作为对照。
- 调试模式允许缩短视觉等待与即时出字；保留变量赋值、条件判断、跳转及
  必需初始化。遇到选择或明确停止点立即停住。
- 调试选项与正常游玩选项分开，正常模式仍保留原作节奏；显示当前脚本与位置，
  方便报告问题。任意场景跳转只用于已知可独立初始化的入口。
- 音频回调只允许更新其所属的当前播放实例，覆盖旧回调、自然结束、播放失败、
  循环、停止后重播等测试。实测对白语音加载、播放和切换，不能只检查文件存在。

验收：同一路径可重复测出明显加速，且结果状态和正常推进一致；选择不被
越过；连续切换语音不会误报停止；播放被浏览器拦截时能通过用户交互恢复。

## 6. 阶段四：手机控制与存读档闭环

先盘点原作每个按钮的实际用途，建立“原作行为 → 兼容实现 → 当前状态”表。
第一批实现存档、读档、历史、自动、快进、隐藏对话框、音量与返回标题。
保留原作的使用习惯，同时扩大触摸目标，避免面板挡住台词或选项。

存读档必须覆盖兼容层自己的状态：图层、页、当前语音/动画策略和变量。
不能只把原作按钮接到 Tyrano 菜单后就宣告完成。未支持的按钮应明确标示
或隐藏，不能呈现为可用但点击无效果。

验收：正文和选择前均能存读档；关闭后重开能恢复；历史顺序正确；自动和
快进可以退出；菜单关闭后回到原来的位置，不重复执行剧情。

## 7. 阶段五：动画与鉴赏

### 动画

按实际用途区分视频、逐帧动画、立绘移动与缩放、转场效果，逐项确认时序、
透明度、层级、循环及停止条件。优先修复影响剧情理解和推进的行为，再改善
纯视觉效果。不支持的效果在能力表中记录，不静默变成空操作。

任何素材批处理先随机选取 3–5 个有代表性的文件测耗时、输出体积与质量，
报告总量预估和瓶颈后再全量运行。允许的视觉降级由试玩结果决定。

### 鉴赏

先查明原作鉴赏入口、缩略图、解锁变量、分页及回想启动方式，再实现相应
页面。正常模式保留解锁规则；调试解锁须显式开启且不能污染正式存档。
复用已有媒体与场景执行能力，不复制另一套剧情状态机。

验收：解锁状态重启后保留；缩略图与内容一致；进入和退出鉴赏不会改坏
主线进度；动画循环及返回操作可靠；手机上无明显持续内存增长。

## 8. 验证与交付规则

| 层次 | 检查内容 | 不能替代什么 |
| --- | --- | --- |
| 单元测试 | 转换正例、反例、边缘情况；合成数据；运行时回调行为 | 真实引擎和画面验证 |
| 构建检查 | 脚本语法、资源引用、未实现标签/API、缓存失效 | 剧情路径正确性 |
| 桌面浏览器 | 阅读、选择、语音、存读档、快进与随机场景回归 | Android 触摸、媒体与性能 |
| Android JoiPlay | 触摸、音画播放、恢复、布局和实际快进表现 | 用户对原作体验的判断 |
| 用户试玩 | 对照六项反馈逐项确认，记录仍需调整的取舍 | 自动化回归 |

本轮没有直接操作 Android 设备的条件；届时由用户实机试玩并提供结果。
截图或外部应用操作无法执行时明确说明，不虚报通过。打包交付前按项目规则
提供试玩版本，获得试玩确认后再打包。源游戏不修改，不自动推送 GitHub。
