# 文档写作规范

本文件规定本仓库全部文档（`README.md`、`AGENTS.md`、`docs/**`）的格式与
用语。依据：GB/T 7713.2—2022《学术论文编写规则》、GB/T 32424—2015《系统
与软件工程 用户文档的设计者和开发者要求》、中文技术文档写作规范。

`tools/check_docs.py` 与 `tests/test_repo_hygiene.py` 不检查本文件的全部
条目；未门禁化的条目由评审把关。

## 1. 硬性用语规则

以下四条是本仓库文档的强约束，与通用规范并列：

1. **不写第一人称叙事**。文档描述事实与做法，不叙述写作者的经历、过程或
   心理活动（「我们试过」「后来发现」「值得注意的是」）。
2. **不引用对话**。不出现「用户要求」「owner 说」「按指示」这类来源；直接
   陈述结论，不要交代结论从何而来。
3. **不写日期**。正文不出现「YYYY-MM 定案」「最近」「目前」「将来」等时间
   表述；版本变化写入 `CHANGELOG.md`。
4. **不写展望与建议**。不写「建议」「应该考虑」「可以扩展」「后续可以」。
   文档写「是什么、怎么做、为什么」，不写「打算做什么」。确实需要记录的
   待办放入对应模块的本地工作区笔记，不入库。

## 2. 结构与标题

- 标题最多四级：一级为文章标题，二级为主要部分，三级为小标题。四级标题
  尽量避免；三级标题下的并列内容用项目列表。
- 一级标题下不得直接出现三级标题；同级标题不得只有一个（避免孤立编号）；
  下级标题不重复上级标题的名字。
- 一个文件只允许一个一级标题。
- 正文段落不缩进；段落之间空一行。

## 3. 文本与句子

- 全角中文与半角英文、数字之间加一个半角空格（`XRuby 插件`、`写入 3 个
  文件`）；半角字符与全角标点之间不加空格。
- 英文单位与数字之间留空隙（`16 GB`）。
- 单句尽量控制在 20 字以内；30 字以上的句子必须语义明确；以逗号分隔的
  长句总长不超过 100 字。
- 使用简单句与并列句，避免复合句；用肯定句，不用双重否定；用主动语态。
- 一个段落只有一个主题，中心句放在段首，段落不超过 7 行。
- 代词（其、该、此）必须指代明确；名词前不加多个修饰语。
- 术语全文统一，首次出现时给出中英文对照或定义：`XP3（KiriKiri 的资源
  归档格式）`。

## 4. 标点与符号

- 中文语句使用全角标点：`，。；：、（）「」`；整句为英文时使用半角标点。
- 并列词用顿号，最后一项用「和」连接。
- 省略号使用 `……`（六点），不使用 `...` 或 `。。。`；省略号不与「等」同用。
- 感叹号尽量避免，不得连用。
- 数值范围用 `～` 或「至」（`2～4 个`、`2 至 4 个`）。
- 半角圆括号用于代码与路径，全角圆括号用于中文补充说明。
- 引号：外层双引号「」或 `""` 按文件既有风格统一，内层单引号。

## 5. 表格、列表与代码

- 表格必须有表头，单元格内容短于说明性文字；同一表格内不要混入段落。
- 项目列表用于并列项；一项一行，不以空行分隔同层项目。
- 代码块必须标语言（` ```bash `、` ```python `、` ```json `），命令与输出
  分开写；路径用代码格式（`rpgmaker/cli.py`）。
- 文件名、命令、标识符、字段名一律用代码格式，不使用引号。
- 代码与注释一律英文，文档一律中文（`AGENTS.md` 语言规则）。

## 6. 事实与口径

- 只写已验证的事实。「已验证」的层次按 `docs/reference/support-matrix.md`
  的口径区分：单元测试、契约测试、构建产物检查、浏览器冒烟、实机验收。
- 不确定的内容不得写入文档；未验证的能力标注为「未验证」，不得省略。
- 不写私密信息：游戏名、密码、本机路径、用户名、渠道名，一律按
  `AGENTS.md` 的公开仓库卫生规则处理。
- 具体游戏的资料写入本地工作区笔记，不入库。
