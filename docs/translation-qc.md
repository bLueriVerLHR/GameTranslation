# 翻译 QC 与故障排查

本文件收集翻译链的失败模式、QC 清单与排障表。流程与命令见
`docs/translation.md`，数据契约与门禁判据见 `docs/translation-data.md`。
v2 的失败模式都有单测钉住；chunk 链的教训按引擎无关的方式阅读，非 MZ 引擎
（TyranoScript、Wolf RPG、KiriKiri）的提取与写回仍走这条链。

## 1. 提取与写回的已知坑

| 坑 | 事实 |
|---|---|
| 命令有两种等价形态 | 编辑器存数组 `[401,0,"…"]`，被工具改写过的数据存命名对象 `{"code":…,"parameters":[…]} `；引擎读命名属性，两者都能跑。只认一种会静默丢掉整部对白。 |
| 纯汉字文本也是真文本 | 地点标签（`\px[200]場所：診察室`）、菜单标签、战斗台词常常没有假名；只靠假名判定会静默漏译一大片。 |
| 名牌归属要看消息窗口 | `\nc<名字>` 常在段落末尾或独占一行；按「含码那一行」判定会错位。按 `101` 命令切窗口，窗口内最后一个名牌标注整个窗口；文本里显式写的 `【名字】` 优先。 |
| 数据库数组索引不能过滤 | MV/MZ 数组索引 0 是 `null`，而键 id 就是数组索引：一旦过滤条目，后面所有 id 全移位，已译内容全部对不上。 |
| 批次必须原子 | 校验全过才写盘是硬要求：真实作品上出现过写偏移 +3、漏译名牌、块错位各一次，都是整批被拦、译文库零污染。 |
| 前导控制码可自动补回 | 续行带重复的开头控制码，漏抄是最高频手误，实测约 60% 的续行条目靠 `--fix-leading` 补回；文本型参数不补，照抄会把日文人名塞回游戏。 |
| 状态文件不能手写 JSON | 一行未转义的反斜杠曾让门禁与进度命令双双崩溃；现改为容错读取并判失败，而不是静默跳过（跳过会掩盖未决问题），并提供 `pending`/`decide` 子命令。 |
| 上下文才是瓶颈 | 长跑里读切片比翻译本身更贵；`slice --lean` 去掉上下文，实测省 57%。 |

## 2. 故障与恢复

执行者在真实作品上失败过两次：一次块错位（自造分隔符），一次命令挂死被中止
（在 Windows 上用了 `/dev/null`）。两次的结果都是译文库零污染，只损失未提交的
那一轮（当时是 1344 条）。恢复方式是让新执行者读磁盘状态接着做，不必人工核对
已译内容，因为门禁本身就是核对。

## 3. chunk 链的 QC 与失败目录

### 每关都跑的清单

1. **逐块**：每块返回后立即跑 `merge_plain_chunks.py`。行数不等于键数就是丢行
   或并行，当场定位。
2. **补丁前值卫生**：折叠双反斜杠（`\\C[27]` → `\C[27]`）、剥离 `【?...】`
   不确定标记、diff 控制码 token 的键值两侧、剔除 identity 条目（`v == k`）。
3. **合并后终检**：跑 `final_qc.py` 查 identity 值、双反斜杠、空值、全键序。
4. **最终构建上的残留假名**：`extract_remaining_text.py` 跑在烘焙后的成品上，
   目标是只剩个位数的有意保留行。walker 必须让顶层列表 JSON
   （`CommonEvents.json`）走事件 walker，否则静默漏掉全部对话。
5. **豁免清单**：作者名、品牌名、拟声词、游戏内标签、数字，预先商定并记录在
   work 目录。

### 失败模式与修复

| 症状 | 根因 | 修复 |
|---|---|---|
| 无返回、无输出文件 | 思考预算耗尽，会话在思考状态结束 | 恢复同一会话并下令立即写文件；文件存在前不结束 |
| 大块首轮无文件（700+ 行） | 一次性写全文件超限 | 分批追加契约（每批 100-130 行，先建文件再逐批追加，每批自检） |
| 缺行（行数少 1） | 漏掉个别键 | 从 `chunks_translated.json` 已有值重建该文件，再逐行对齐签名 |
| 值 = 键原文 + 译文（整块 mismatch） | 把键抄进了值 | `fix_key_prefix.py`：剥掉 `v[len(k):].lstrip("\n")`，机械且幂等 |
| 字面 `\n` 与真实换行混淆 | 把键内嵌的 `\n` 写成了真实换行 | `fix_literal_nl.py`（单行键：`v.replace("\n", "\\n")`）与 `fix_dbl_nl.py` |
| 键尾 `\n` 丢失 | DB 描述丢尾部换行 | 按原文的换行数把尾部 `\n` 补回值尾 |
| `===KEY===` 分隔符全丢 | 写成一个大 blob | 仅当行数等于键数且无多行键时按行重建 1:1 |
| 静默漏键错位（最危险） | 跳过一个键，之后每个值都错位一格 | 把 `keys[i]` 与 `entries[i]` 并排打印，找到错位起点与缺失键，在准确索引插入译文，丢弃所有先前错插的条目（后续移位会变成毒丸） |
| 控制码整块丢失却声称保留 | 自述不可信 | `\TA_` 类码总在行首，机械前缀补回；QC 必须 diff 控制 token |
| `\N[1]` 被硬编码成人名 | 用角色名代替了宏 | 恢复宏，每行只补缺失数量 |
| `\RB[a,b]` 注音参数被译后 QC 误报 | 参数被合理翻译 | QC 改用签名比较（token 名加参数个数，忽略参数内容），且排序后比较（渲染安全） |
| `【原文】` 被误报为 `【?】` | 游戏文本合法使用括号 | UNCERTAIN 正则只匹配 `【...?...】` |
| 幻觉添加行（`<hideIfOwned>` 一类） | 脑补内容 | 值行数归一化到键：补 `""`、截断多余 |
| 值含假名片段 | 部分翻译 | 真翻译，绝不做字符替换；`clean_kana_ticks.py` 对日文有破坏性（ん→嗯、ッ→!），只能跑在中文带尾缀残留的值上，绝不碰真实日文片段，绝不碰 `kind=plugin` |
| 语境误译（`【?】` 或可疑措辞） | 缺场景上下文 | 去 `data/` 定位键（地图或 CommonEvents 相邻 `401` 行），读前后 5 行，手工定稿 |
| 脚本跑两遍、二次污染 | 修复脚本跑了两次 | 修复脚本必须幂等，或者只跑一次 |

### 编排脚本时的坑

- 任何修复脚本跑两遍就是双重污染。
- 修错位时先把 `keys[i]`/`entries[i]` 并排打印，确认错位起点和缺失键再动手；
  先插了再说是把文件搞得更乱。
- PowerShell 转义：用 `python -c "..."` 写正则会二次转义 `\`；诊断一律写成
  `.py` 文件。
- `re.sub` 的替换串含 `\N` 会报 bad escape；改用 `lambda m: ...`。
- plain 文件重写格式：条目之间是 `\n===KEY===\n`，用
  `"===KEY===\n".join(parts)` 构建，不是 `MARK + "\n".join(...)`，后者会毁文件。

### 实测口径

- 第一道 QC 门永远是行数，其他都是次要。
- 写原始 `\C[27]`（单反斜杠）时文件里是单个 `\` 而应为 `\\`，卫生遍历负责
  折叠或反转义。
- 偶尔会整条丢掉含原始控制码的键（`\C[14]`），行数不匹配会抓到，手工补。
- `\n` 行数必须与键完全一致。
- 必须保持原样、既不翻译也不修复的假名误报：
  - 控制码参数：`\fn[字体名]` 的字体名、`\F1[n]`、`\C[xx]`；
  - note 里的插件标签参数（`<拡張説明:…>` 分类参数、`<反転なし>`、
    `<一時自動蘇生>`）；
  - 音频与头像文件名：码 `250`/`241`/`249` 的 SE/BGM/ME
    `parameters[0].name`、地图 `bgm`/`bgs` 的 `name`、码 `101`
    `parameters[0]` 的头像文件名；
  - 消音 gag 标记（`■ィ■■`）与故意的 mojibake gag。
- 烘焙后重扫对话行（`401`/`405`，剥离控制参数）。

## 4. 术语一致性

### MTool 字典先审计

随包字典经常自相矛盾：一个物品、地点或角色有 2 到 4 种译法。用字典预填前先
审计同一日文键族的不同译文（同一物品名三种译法、一个条目音译另一个意译），
每族定一个（语义匹配或最高频），其余用 sweep 统一。常见分歧类：品牌与药名
（`Z`/`X` 后缀）、食物、地名、带敬语的名字。还要查作者自身的不一致：同一角色
全文两种写法时按确认过的词表统一。

### sweep 的 substring bomb

目标串是另一条规则目标的前缀时产生垃圾：`色经验值 → 色色经验值` 会命中已 sweep
出的 `色色经验值`，得到 `色色色经验值`。规则：任何目标串包含另一规则目标串的
替换必须顺序敏感或整词匹配；sweep 后全库搜目标串确认没有畸形产物。

### identity 值

中日同形汉字（主人公、命中率、防御力）可接受；日文特有词必须翻（就寝前、防具、
音量这类日式用词）。场景名、开关名、变量名也在范围内，别因为像内部标签就跳过。

成人词汇的中日对照与判定表属于游戏专属数据，只放本地跨游戏通用词表目录
（gitignored），不写进本仓库文档。

## 5. 按名称查找的引用只翻一边会坏

按显示名解析实体的插件标签，在被引名翻译了而引用没翻（或反之）时会坏掉：

- `<TE:name>`（TemplateEvent）：事件 note 带模板名；模板地图的事件名被翻译，
  按名查找失败，无条件 autorun 事件永不擦除，`isEventRunning()` 恒为 true，
  结果是玩家永远无法移动。
- `<namePop:name>` 气泡名、`callEventByName`、`searchDataItem(...,'name',...)`、
  BalloonPlus 气泡名、MPP_ChoiceEX 标签文本。

`tools/bake_translation.py` 用字典同步 `<TE:>`/`<namePop:>` 引用
（`_translate_note_refs()`，跳过含控制码的引用），结尾把每个引用对照游戏事件名，
dangling 引用（含因带控制码被跳过翻译的）逐一 WARN。其他插件用 `rg` 扫按名称
查找的模式，两侧一致地翻译。

## 6. 故障排查表

| 症状 | 修复 |
|---|---|
| 执行者无返回、无输出文件 | 恢复同一会话并下令立即写文件，新开一个常以同样方式失败；块过大就把剩余键分得更小：`gen_translation_shards.py <work_dir> --resume --start N`（auto 选档，或用 `--context-budget-kb 60` 收紧上下文） |
| 上下文文件过大、反复卡住 | 压缩上下文：`--window 1`、45 字符截断、窗口去重、词表上限约 40 条；`context.md` 控制在 90 KB 以内，90KB 以上的密集块是 flaky 失败的温床 |
| zh.txt 行数不等于 ja.txt 行数 | 丢行或并行。修 zh.txt 的行（绝不碰 ja.txt），重跑 `merge_plain_chunks.py`；丢掉含控制码的键（`\C[14]`）表现相同，手工补 |
| zh.txt 含原始 `\C[27]`（单反斜杠） | 字面反斜杠必须写 `\\`；修该行再合并 |
| 输出缺某些键 | 1:1 行布局下缺键就是行数不匹配（上条）；否则块被拆到多个 zh 文件，每块独立合并 |
| 消息窗口文本溢出 | 值行数多于键时追加命令，少于键时补空行；翻译时保持行数相等 |
| 中文显示方块 | 烘焙器自动应用标准字体策略（chunk 链用 `bake_translation.py` 的 `--cjk-font` 与 `--jp-font`，v2 用 `bake` 的 `--font-policy`；字体清单与解析顺序见 `docs/reference/local-layout.md` §4–5）。仍不行就装 CJK 字体（微软雅黑、Noto Sans CJK） |
| 实际是文件名或标签的残留假名 | `\fn[字体名]`、SE/BGM/ME `parameters[0].name`（码 250/241/249）、地图 `bgm`/`bgs` 的 `name`、码 101 `parameters[0]` 的头像文件名、note 插件标签参数，都不翻译；假名检查前先剥离控制 token |
| 插件参数里的菜单文本没翻 | 只有 `build_translation.py` 未带 `--no-plugins` 且字符串含日文时才提取（kind `plugin`）；重跑提取、翻译、重烘焙。插件命令参数（码 `356`/`357`/`657`/`355`）里引号外的功能性部分绝不静态翻译；显示值（`357` 参数对象里的字符串、`122` 脚本字符串字面量、`355`/`655` 引号内含假名的行、Troops 战斗事件）按 `docs/archive/translation-v1.md` §3 的规则补翻 |
| 插件按日文名查找的功能键被翻坏（选择帮助命令名被译成中文后，事件注释里的日文标记失配，帮助文本消失） | 功能键（事件注释、note 与插件参数里的同名匹配串）必须逐字豁免：从字典里删掉该键，`plugin_json_leaves` 与合并时走 `--exempt`，再烘焙 |
| 选择肢失效（分支走错） | 码 `102` 与 `402` 共享键，两侧自动同步 |
| 翻译后玩家无法移动（`isEventRunning()` 恒 true，事件 `_starting` 卡住） | TemplateEvent `<TE:name>` 的 note 引用失配。用 `tools/bake_translation.py` 重新烘焙（它同步 `<TE:>` 引用并对 dangling 引用 WARN），见 §5 |
| `\N[1]` 类名字保持日文 | 那是宏：显示文本来自 `Actors.json`，角色的 `name` 必须翻译（是普通 DB 键）；码本身绝不译 |
